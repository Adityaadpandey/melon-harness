Codex CLI is OpenAI's terminal coding agent. zerd is a terminal agent that works with many providers, OpenAI among them. zerd can sign in with your ChatGPT/Codex login, so you can try it without a new key.

Details about Codex CLI on this page are limited to its well-known design. For its exact current options, see OpenAI's docs.

## At a glance

| | zerd | Codex CLI |
|---|---|---|
| Models | Codex login over the Responses API, plus [15 built-in providers](/docs/models) and any OpenAI or Anthropic format server | OpenAI models |
| Provider fails | Fails over to another provider, blocks the failing one for the session and tells you | One vendor |
| After an edit | Picks checks for only the changed files and runs them, with up to 2 repair rounds, then escalates to a strong model | The model decides what to run |
| Failure not caused by the agent | Detected by re-running on the pre-run files, left alone, run ends `unverified` | Up to the model |
| Review | A second model reviews the real diff, a verifier refutes weak findings | Review on request |
| Paths in the answer | Every `path` and `path:line` is checked on disk | Not checked |
| Sandbox | Confined file tools, shell path scan, macOS `sandbox-exec` | OS sandboxing with approval modes |
| Approval modes | `on-request`, `auto-edit`, `auto`, `plan`, `never`, `on-failure`, `yolo` | Approval modes |
| Written in | Rust, one binary | Rust |
| Source | Source-available, free to run | Open source |

## Using your Codex login in zerd

Pick where models come from during first-run setup: a ChatGPT/Codex login, an Anthropic, OpenAI, OpenRouter or Gemini key, a local Ollama or LM Studio, or a gateway. A model id such as `codex/gpt-5.6-luna` goes through your Codex login. The 11-task benchmark against Claude Code ran zerd on exactly that model. See [Models and routing](/docs/models).

You can then add more providers per role in `config.toml`, for example a cheap model for `fast` and a different family for `review`:

```toml
[routing]
default = ["claude-sonnet-5-5", "deepseek/deepseek-v4-pro"]
fast    = ["deepseek/deepseek-v4.1-flash"]
strong  = ["claude-opus-5-5"]
review  = ["gpt-5.6-sol"]
```

## What zerd adds

**Verification is the default in scripts.** One-shot, `--json` and `--rpc` runs check changed files automatically after edits, with repair rounds, because nobody is there to ask. Interactive runs check when you run `/verify` or ask for a review.

**A second family reviews.** The advisor and challenger default to a different model family than the author, so they do not share blind spots.

**Failure always has a next step.** Checks fail, then repair. Repair fails, then the strong model. A loop is detected, then escalate, then stop. Budget low, then one last tool-free call turns what was learned into an answer.

**Rounds are estimated and scored.** The model names how many tool rounds a task needs, zerd scores the guess and prints it, and the hard stop is 3 times the guess, never below 25 rounds.

## How zerd works differently

**It knows whose failure it is.** When a check fails, zerd swaps in the pre-run copy of your files, runs the same check again, and puts the agent's files back. An error that was already there is reported as "was already failing before your change; leaving it alone", and the run ends `unverified`. Failures the agent caused go back as a repair request, up to 2 rounds, then to the strong model.

**The author never grades its own work.** A different model reviews the real diff in a fresh context with read-only tools. A verifier tries to refute each finding, six at a time, naming the exact line it read. A confirmed HIGH goes to a repro agent in a sandboxed copy; if it cannot make the defect happen, the finding is capped at MEDIUM.

**It will not invent files.** Every `path` and `path:line` in the final answer is looked up in the real tree. An invented file or a line past the end of one goes back for one correction.

**Every run ends in an honest status:** `verified`, `unverified`, `verification_failed`, `failed` or `done_no_changes`. Never a bare "done".

## What the benchmarks do and do not show

zerd has been benchmarked head to head against Claude Code only, in two rounds. There is no head-to-head against Codex CLI, so nothing below is a claim about it. What the rounds do show is how zerd's approach behaves:

| | zerd |
|---|---|
| 11 tasks, one run each | 10 / 11 passed, the miss became the [signature guard](/docs/verification) |
| Input served from cache | 87% (85% in a real 21-call session) |
| Webhook reliability test, 15 scenarios | 15 / 15 with an automated test, 12 real bugs found against real PostgreSQL, real Redis and a real SIGKILL |

One project, one run each, and the agents did not test at the same depth. Details and caveats are on the [Benchmarks](/docs/benchmarks) page.

## Where Codex CLI is ahead

- **It is open source.** zerd is source-available. See the [license](/docs/license).
- **First-party OpenAI integration**, built by the team that makes the models.
- zerd's OS sandbox is macOS only, and zerd has no IDE extension or image input yet ([Limits](/docs/limits)).

## Which should you use

Choose Codex CLI if you want OpenAI's own agent and plan to stay on OpenAI models. Choose zerd if you want proof on every change, more than one provider with failover, or a second model reviewing the work.
